Skool Comp #13 — "The Translator"

A converter with a contract, not a summarizer with good intentions.

Turns one incident-driven teaching essay into a fixed 8-slide carousel — same shape every run, every claim traced back to the exact paragraph and sentence it came from, checked by an offline verifier before anything ships. Nothing invented. Nothing that matters silently dropped.

See a real translation Watch it get attacked

What you get

Eight fixed roles, every run, in this order. A role with nothing to fill it says so — it never guesses.

  • 1Hookthe essay's own opening tension/contradiction
  • 2Incidentthe concrete event that happened
  • 3Revealwhat turned out to be true, contradicting the first guess
  • 4Insightthe compressed, quotable lesson
  • 5Rule-or-Citationa named external source, if the essay cites one — else "not in source"
  • 6Confirmation-at-scaleevidence the pattern isn't a one-off, if present
  • 7Mechanismthe underlying structural fix, if described
  • 8Closethe essay's own final thought — no CTA, no link

How grounding actually works

Every populated field carries one or more citations — a quote plus a p<N>s<M> coordinate (paragraph, sentence). verify.py checks each quote as a literal substring of that specific location, ±1 sentence for boundary drift, never crossing into a neighboring paragraph. A real fact cited under the wrong-but-nearby location still fails — that narrowness is the whole point. Full mechanism in reference/grounding-methodology.md.

Grounded correctly

{"quote": "build it, use it, trust it, and then orchestrate it", "loc": "p5s1"} — checked against paragraph 5, sentence 1's window. Found. Passes.

Caught as a failure

{"quote": "...nineteen retries...", "loc": "p1s2"} — the real 19-retries fact, cited under the wrong (12-retries) paragraph. Not found there. Fails — on purpose.

What this honestly doesn't check

Same two-track honesty as this worker's own can-spam-auditor build: grounding is fully mechanical, extraction judgment isn't.

Does the offline checker generate translations?

No. verify.py verifies a given output against a given essay — it doesn't produce one. The extraction (deciding what's Hook vs. Insight, reading the essay) is done by whoever is loaded with identity.md/rules.md/examples.md, same as every other specialist this worker builds.

Can it catch a citation of the wrong self-corrected value?

Not mechanically. If an essay states a fact then corrects it, both values are literally present in the text — a citation of either would ground successfully. Resolving to the corrected value is a rule taught in rules.md and demonstrated in examples.md, not something the offline checker enforces. See fixtures/manifest.md § Known boundary.

Setup

  1. Clone the repo. Python 3.9+, nothing else — no pip install.
  2. Confirm the checker works: python3 verify.py --selftest.
  3. Watch it get attacked: python3 verify.py --judge-mode.
  4. Verify a real translation by hand: python3 verify.py fixtures/essay-1-dont-automate.md fixtures/essay-1-dont-automate.output.json.
  5. Translate a new essay: load identity.md/rules.md/examples.md/reference/ into a Claude Project (code execution enabled), paste in an essay matching the genre in reference/genre-notes.md, and ask for a translation.
